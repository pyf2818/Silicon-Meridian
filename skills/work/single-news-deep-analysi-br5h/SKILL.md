# 单条高价值情报的深度研判流程

## 适用场景
用户抛出一条资讯（可能带 [资讯:ID]），要求分析/研判/解读。目标是给出可决策的结论，而不是复述新闻。

## 工作流程（四步法）
1. **并行拉证据**（一次消息内发起全部调用，节省往返）：
   - search_news(关键词) → 补充同主题资讯与背景
   - read_intelligence_focus(主题) → 拉聚焦证据链，拿到可直接引用的 [资讯:ID]
   - list_knowledge(关键词) → 查历史沉淀，避免重复分析、衔接旧结论
2. **证据分级**：官方公告/厂商自证默认可信度降一档（单源、无交叉验证）；联网补充信源仅作方向性佐证，不可用 [资讯:ID] 引用；区分「可验证事实」与「媒体解读」
3. **横向关联**：在当日资讯库内找同类事件（同公司/同领域/同治理议题），串成趋势判断——单条资讯的价值在于它与其他条目的共振
4. **结构化输出 + 沉淀**：
   - 输出：一句话结论 → 优先级(P0/P1/P2) → 关键依据表 → 影响评估表 → 证据强度提示 → 下一步动作（至少3个可选方向）
   - 沉淀：save_knowledge 保存「判断记录」（事实确认/关联事件/判断结论/观察点/引用限制五段式）

## 关键决策点与陷阱
- 优先级判定依据：事件性质（分水岭 vs 常规进展）× 用户关注命中度 × 时间维度（即刻生效 vs 远期）
- 陷阱1：把「官方自证」当独立事实——必须标注置信度与单源状态
- 陷阱2：只讲事件本身不讲影响传导——必须落到「对用户关注领域意味着什么」
- 陷阱3：忘记查历史沉淀——list_knowledge 先查，避免重复劳动
- 引用纪律：只用证据集内 [资讯:ID]，不得编造；素材库引用用 [素材:ID] 并标注类型

## 输出模板（Markdown）
```
## 一句话结论
## 优先级判断：P0/P1/P2
| 维度 | 评估 |
## 关键依据（事实链 + 横向对照）
## 影响评估（按影响对象分列）
## 证据强度提示
## 下一步动作（3个可选方向）
```

## 工具使用经验
- read_intelligence_focus 的 topic 用「公司+领域」组合（如 "OpenAI 安全 网络安全"）比单一关键词召回更准
- search_news 查不到时工具会自动联网兜底，注意把联网结果与资讯库结果分开标注
- save_knowledge 的 content 用五段式结构，标题带上日期与事件关键词，便于后续检索召回
- create_skill 的 title 必须用英文 kebab-case（如 single-news-deep-analysis），中文标题会导致 skill id 非法
