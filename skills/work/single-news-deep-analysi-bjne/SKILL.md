# 技能标题：单条高价值资讯的深度研判（single-news-deep-analysis）

## 适用场景
- 什么时候使用：用户抛出一条资讯（可能带 [资讯:ID]），要求"分析这条 / 研判 / 深度解读 / 这条怎么看"；目标是把单条新闻变成可决策的情报判断，而不是复述新闻内容。
- 典型触发词：分析这条、研判、深度解读、这条资讯怎么看、情报深度分析、深度分析。
- 变体：用户给出多个 [资讯:ID] 时同样适用，只是把"单条深挖"扩展为"多条目横向对撞"。

## 工作流程与方法论
1. **第一步：并行拉证据（一次消息内并发全部调用，节省往返）**
   - search_news(关键词)：在当日资讯库补同主题条目，找背景与对照
   - read_intelligence_focus(主题)：拉聚焦证据链，获得可直接引用的 [资讯:ID]
   - list_knowledge(关键词)：查历史沉淀，衔接旧结论、避免重复分析
   - 为什么并行：三路信源互相独立，无依赖关系，串行会浪费至少两轮等待。
2. **第二步：证据分级（关键判断标准）**
   - 官方公告/厂商自证：默认可信度降一档，标注"单源、置信度 xx%"
   - 资讯库条目：可引用为 [资讯:ID]；联网兜底结果仅作方向性佐证，不可用 [资讯:ID] 引用
   - 区分"可验证事实"（能力描述、日期、数字）与"媒体解读"（动机揣测、影响预测）
3. **第三步：横向关联 + 趋势串线**
   - 在当日资讯库内找同类事件（同公司/同领域/同治理议题），判断单条事件是孤立个案还是行业信号
   - 注意事项：不要停留在"这条新闻说了什么"，要落到"这条和其他条目共振后意味着什么趋势"
4. **第四步：结构化输出 + 沉淀**
   - 输出按模板（见下），结论先行
   - 用 save_knowledge 沉淀"判断记录"（事实确认/关联事件/判断结论/观察点/引用限制五段式），标题带日期+事件关键词便于召回

## 关键决策点
- **优先级判定**：P0 = 分水岭事件 × 命中用户核心关注 × 即刻生效；P1 = 重要进展但影响 6-12 个月内传导；P2 = 常规更新。三者取交集强度定级。
- **何时调整策略**：
  - 证据多且可交叉验证 → 置信度上调，结论可以更果断
  - 核心事实只有单源自证 → 明确降档并给出观察点，不替厂商背书
  - 用户关注领域外但行业影响力大 → 降优先级但保留"为什么仍需注意"一句
- **常见陷阱**：
  - 陷阱1：把官方自证当独立事实——必须标注单源状态与置信度
  - 陷阱2：只讲事件不讲传导——必须落到"对用户关注领域意味着什么"
  - 陷阱3：跳过 list_knowledge 导致重复分析、与旧结论矛盾
  - 陷阱4：编造 [资讯:ID] 或把联网信源冒充证据集条目——引用纪律是硬约束
  - 陷阱5：create_skill 的 title 用中文导致 skill id 非法——必须用英文 kebab-case（如 single-news-deep-analysis）

## 工具使用经验
- 本次用到的工具及作用：
  - search_news：补同主题条目与背景；查不到时自动联网兜底，但兜底结果与资讯库结果分开标注
  - read_intelligence_focus：拉聚焦证据链，产出可直接引用的 [资讯:ID]
  - list_knowledge：查历史沉淀，衔接旧结论
  - save_knowledge：沉淀判断记录，供后续检索召回
- 最佳实践：
  - read_intelligence_focus 的 topic 用「公司+领域」组合（如 "OpenAI 安全 网络安全"）比单一关键词召回更准
  - 证据拉取阶段四工具并发（含 save_knowledge 可在结论确定后单独发），依赖关系上"先证据后结论"
  - 沉淀内容用五段式，标题公式：`<公司/主体> <事件>：<判断>（<日期>）`

## 输出模板
最终交付物包含五个部分：
1. **一句话结论**：先给判断，不超过两行
2. **优先级判断**：P0/P1/P2 + 判定理由（事件性质 × 关注命中 × 时间维度）
3. **关键依据**：表格呈现事实链（每条带 [资讯:ID]）+ 横向对照事件
4. **影响评估**：按影响对象分列（如行业格局/监管/生态/用户领域），各含时间维度与观察信号
5. **证据强度提示 + 下一步动作**：明确标注单源/降档状态；下一步给至少 3 个可选动作（深化信源、对标事件、落地应用、写简报等）

格式要求：全中文，禁用 emoji 与装饰符号，结论前置，表格承载对比型数据，末尾必须有"下一步动作"。
