# 代码评审清单

对一段代码或 PR diff 做八维结构化评审，输出"通过/有条件通过/需修改"的明确判断与可执行改进项。

## Prompt 模板

```
请按八维清单评审以下代码：

【代码内容】
{codeSnippet}

【上下文】
{context}（语言/框架/项目背景，用户提供）

【输出结构】
1. 总体判断：通过 / 有条件通过 / 需修改
2. 八维评审（每维 1-2 句话 + 通过/警告/问题标记）：
   - 正确性：逻辑是否正确，边界条件是否处理
   - 安全性：注入/XSS/越权/敏感信息泄漏/依赖漏洞
   - 性能：时间/空间复杂度，N+1 查询，不必要的同步阻塞
   - 可读性：命名/注释/结构清晰度
   - 测试：是否有对应测试，覆盖关键路径与边界
   - 兼容性：版本依赖/平台差异/向后兼容
   - 边界条件：空值/超大输入/并发/网络异常
   - 可维护性：耦合度/扩展性/魔数与硬编码
3. 必改项（blocker，列出具体行号与修改建议）
4. 建议改进项（non-blocker，可选优化）
5. 赞赏项（值得学习的好实践，若有）

【风格要求】
- 问题必须附具体行号或代码片段
- 修改建议给出可粘贴的代码示例
- 区分"必须改"与"建议改"，不模糊
- 不评判代码风格个人偏好（如 tab vs space）
```

## 使用示例

用户输入："帮我 review 这段代码" / "评审一下这个 PR"

Agent 匹配 triggers 后：
1. 直接按八维清单处理用户提供的代码
2. 必改项用代码块给出修改示例
3. 末尾给出明确的"是否可合并"判断

## 注意事项

- 不依赖工具调用，纯文本评审
- 若代码片段过短或缺乏上下文，明确指出"无法判断 X，需补充 Y"
- 涉及特定框架/库时，主动提示"假设使用 X vN，若版本不同结论可能变化"
- 安全问题一律列为 blocker，不论严重程度
- 性能问题需说明"在什么量级下会成为瓶颈"
- 不替作者重写整段代码，只给关键改进点
