# GitHub 仓库评估

对 GitHub 仓库进行结构化评估，输出场景适配、目标受众、上手难度、综合价值四个维度的判断。

## Prompt 模板

```
请评估以下 GitHub 仓库：

【仓库信息】
{repoUrl}

【输出结构】
1. 一句话定位（项目是什么）
2. 场景适配（1-5 分）：与用户当前关注领域的匹配度
   - 用户兴趣领域：{userInterests}
   - 说明匹配理由
3. 目标受众（枚举）：
   - 个人开发者 / 团队 / 企业 / 研究 / 教育
   - 说明判断依据
4. 上手难度（1-5 分）：
   - 文档完整度 / 示例丰富度 / 依赖复杂度
5. 综合价值（1-5 分）：
   - 技术创新性 / 社区活跃度 / 维护可持续性
6. 建议：是否值得深入 / 如何快速验证 / 潜在风险

【数据来源】
- 优先抓取 README
- 参考 star/fork/issue 趋势
- 最近提交活跃度
```

## 使用示例

用户输入："评估一下 https://github.com/xxx/yyy"

Agent 匹配 triggers 后：
1. 调用 `fetch_page` 抓取仓库 README
2. 可选 `web_search` 补充社区评价
3. 按模板结构输出评估
4. 在末尾给出"建议深入 / 暂时搁置"的明确判断

## 评估维度说明

| 维度 | 1 分 | 5 分 |
|------|------|------|
| 场景适配 | 与用户兴趣完全无关 | 高度匹配用户核心领域 |
| 上手难度 | 文档缺失，依赖复杂 | 文档详尽，开箱即用 |
| 综合价值 | 技术陈旧，社区萎缩 | 创新性强，社区活跃 |

## 注意事项

- 评估必须基于真实抓取的数据，不可凭仓库名臆测
- star 数不是唯一标准，需结合提交频率/issue 响应速度
- 涉及商业项目时需说明许可证限制
- 若仓库为空或已归档，直接说明并跳过评估
